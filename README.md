# Урсгалын сан — Ажиллагчдын төлөв

**F.CSM302 Үйлдлийн систем · V-1-9 · Designing a Thread Pool**

Энэ төсөл нь олон ажлыг урьдчилан үүсгэсэн цөөн тооны ажиллагч урсгалаар (*worker thread*) хуваарилан гүйцэтгэх зарчмыг харуулах Java программ юм. Ажил ирэхэд чөлөөтэй урсгал түүнийг авч гүйцэтгэнэ. Бүх урсгал завгүй бол дараагийн ажлууд дараалалд хүлээнэ. Ажил дууссан урсгал дахин ашиглагдана.

Программын гол зорилго нь **ажлын дараалал, урсгалуудын зэрэгцээ ажиллагаа, төлөвийн өөрчлөлтийг бодит хугацаанд ажиглах** юм. Үндсэн Thread Pool-ийг Java-ийн `Thread`, `Runnable` болон synchronization механизмаар өөрсдөө хэрэгжүүлсэн; бэлэн `ExecutorService` ашиглан сан үүсгээгүй.

## Үндсэн боломжууд

- **Ажиллагчдын тоог сонгох:** 1–32 урсгал үүсгэж, ажлуудын гүйцэтгэлийг харьцуулна.
- **Ажлын дараалал:** Хүлээж буй ажлуудыг FIFO дарааллаар хадгална. Дарааллын багтаамжийг 1–1000 хооронд тохируулна.
- **Ажлын параметр:** Нэг удаад нэмэх ажлын тоо (1–100), үргэлжлэх хугацаа (100–15000 мс), ажлын төрлийг өөрчилнө.
- **Гурван төрлийн ажил:** Хүлээлт (I/O загвар), CPU тооцоолол, Алдаа шалгах.
- **Ажиллагчдын төлөв:** Ажиллагч бүрийн **СУЛ**, **АЖИЛЛАЖ БУЙ**, **ЗОГССОН** төлөв, дуусгасан ажлын тоог харуулна.
- **Хугацааны шугам:** Хэзээ ажиллаж, хэзээ сул байсан, хэзээ ажил дууссан эсвэл урсгал зогссоныг тэмдэглэнэ.
- **Ажлын түүх ба бүртгэл:** Ажлын ID, төлөв, гүйцэтгэсэн ажиллагч, эхэлсэн/дууссан хугацаа болон үйл явдлуудыг харуулна.
- **Зогсоох ба шинэчлэх:** Ажиллагчдад таслах дохио өгч, хүлээж буй ажлуудыг цуцална. Дараагийн туршилтад шинэ тохиргоогоор эхэлж болно.

Программ нь жинхэнэ Java урсгалууд ажиллуулдаг. Харин I/O төрлийн ажилд бодит файл эсвэл сүлжээний хүсэлт хийхийн оронд `Thread.sleep()` ашиглан хүлээлтийг загварчилдаг.

## Ажиллуулах заавар

**Шаардлага:** JDK 17 ба түүнээс дээш хувилбар, Java программыг ажиллуулах боломжтой график орчин. Bash терминалтай бол бэлдсэн скриптүүдийг шууд ашиглаж болно. Нэмэлт Java сан суулгах шаардлагагүй.

GitHub-оос төслөө татахдаа `git clone` ашиглана. Төслийн үндсэн хавтсанд `src/`, `tests/`, `run.sh`, `test.sh` файлууд байна.

**1. Java суусан эсэхийг шалгах:**

```bash
java -version
javac -version
```

**2. Төслийн үндсэн хавтаснаас программыг нээх:**

```bash
bash run.sh
```

`run.sh` нь эх кодыг compile хийгээд `Main` классыг ажиллуулна. Bash скрипт ашиглахгүй бол Java-ийн командуудаар мөн ажиллуулж болно:

```bash
mkdir -p out
javac -encoding UTF-8 -d out src/*.java
java -Dfile.encoding=UTF-8 -cp out Main
```

Амжилттай ажиллахад **“УРСГАЛЫН САН / АЖИЛЛАГЧДЫН ТӨЛӨВ”** гэсэн график цонх нээгдэнэ.

## Программыг ашиглах

| Тохиргоо, товчлуур | Үүрэг |
|---|---|
| Ажиллагчдын тоо | Зэрэг ажиллах боломжтой урсгалын тоо |
| Дарааллын багтаамж | Зөвхөн хүлээж буй ажлуудын дээд тоо; одоо ажиллаж буй ажлууд үүнд орохгүй |
| Нэмэх ажлын тоо | Нэг даралтаар нэмэх task-ийн тоо |
| Хугацаа (мс) | Нэг ажлын төлөвлөсөн хугацаа; 1000 мс = 1 секунд |
| Ажлын төрөл | Хүлээлт, CPU тооцоолол эсвэл алдааны туршилт |
| Сан үүсгэх | Сонгосон тооны ажиллагч урсгал үүсгэх |
| Ажил нэмэх | Шинэ ажлуудыг дараалалд оруулах |
| Зогсоох | Хүлээж буй ажлыг цуцалж, ажиллагчдад `interrupt()` дохио өгөх |
| Шинэчлэх | Өмнөх санг зогсоож, шинэ туршилтын тохиргоо сонгох |

Эхлээд **“Сан үүсгэх”**, дараа нь **“Ажил нэмэх”** дарна. Ажиллагч сул байгаа үед дарааллаас ажил авна; сул ажиллагч байхгүй бол ажил хүлээнэ. Дараалал дүүрсэн тохиолдолд программ нэмэлт ажлыг хүлээн авахгүй, шалтгааныг мэдээлнэ.

### Дэлгэц дээрх төлөвүүд

| Тэмдэглэгээ | Утга |
|---|---|
| Саарал | Ажиллагч сул, шинэ ажил хүлээж байна (`IDLE`) |
| Ногоон | Ажиллагч ажил гүйцэтгэж байна (`RUNNING`) |
| Цэнхэр босоо тэмдэг | Ажил амжилттай дууссан агшин (`COMPLETED`) |
| Улаан босоо тэмдэг | Ажиллагч зогссон эсвэл тасалдал/алдааны үйл явдал бүртгэгдсэн агшин |

`COMPLETED` нь ажлын үр дүн, харин `IDLE` нь ажиллагчийн тухайн үеийн төлөв юм. Тиймээс нэг ажил дуусмагц ажиллагч дараагийн ажил хүлээхдээ буцаад сул төлөвт шилждэг. Ажлын өөрийнх нь **ДУУССАН**, **АЛДААТАЙ**, **ЦУЦЛАГДСАН** төлөв **“Ажлын түүх”** хэсэгт үлдэнэ.

## Туршилтын жишээнүүд

### 1. Олон ажиллагчтай үндсэн туршилт

| Тохиргоо | Утга |
|---|---|
| Ажиллагчдын тоо | 3 |
| Дарааллын багтаамж | 30 |
| Нэмэх ажлын тоо | 8 |
| Нэг ажлын хугацаа | 2000 мс |
| Ажлын төрөл | Хүлээлт (I/O загвар) |

**“Сан үүсгэх” → “Ажил нэмэх”** дарахад эхний ажлуудыг сул ажиллагчид авч, үлдсэн нь дараалалд орно. Ажлууд дуусах тусам дараалал багасна. Зогсоох товч даралгүй хүлээвэл амжилттай туршилтын төгсгөлд **Нийт = 8, Дууссан = 8, Хүлээж буй = 0, Ажиллаж буй = 0** болно. Яг аль ажиллагч аль ажлыг авах нь ажиллуулах бүрд өөр байж болно.

### 2. Ажиллагчдын тоог харьцуулах

Нэг ижил төрлийн, ижил хугацаатай 6 ажлыг эхлээд 1 ажиллагч, дараа нь 3 ажиллагчаар гүйцэтгүүлнэ. Туршилт бүрийн хооронд **“Шинэчлэх”** дарж шинээр эхэлнэ. Хугацааны шугамаас нэг ажиллагчтай үед ажлууд дарааллан, олон ажиллагчтай үед зэрэг гүйцэтгэгдэж байгааг ажиглана.

Үндсэн `ThreadPool` класс нь `ThreadPool()`, `ThreadPool(int size)`, `add(Runnable)` болон `shutdown()` гэсэн методтой. UI-д хэрэгтэй мэдээллийг авахын тулд task-ийн бүртгэл, event болон snapshot зэрэг нэмэлт боломжуудыг оруулсан.

## Хэрэгжилтийн гол санаа

Ажлуудыг `ArrayDeque` дараалалд хадгалж, нэг lock-оор хамгаалдаг. Ажиллагчид queue-ээс нэг нэгээр нь ажил авах тул нэг task-ийг хоёр урсгал зэрэг авахгүй. Ажил байхгүй үед `wait()` ашиглан хүлээж, шинэ ажил нэмэгдэхэд `notifyAll()` ашиглан сэрээнэ.

Ажиллагч task-ийг queue-ээс авсны дараа lock-ийг чөлөөлж, ажлаа гүйцэтгэнэ. Ингэснээр бусад ажиллагч ижил хугацаанд өөр ажил хийх боломжтой. Төлөвийн өөрчлөлт болон хугацааг бүртгэж, UI-д харуулдаг.

## Анхаарах зүйлс

- Энэ нь хэрэглээний түвшний Java thread pool; үйлдлийн системийн kernel scheduler-ийг орлохгүй.
- FIFO дараалал нь ажил авах дарааллыг тогтооно. Олон урсгал зэрэг ажиллах тул ажлуудын дуусах дараалал ялгаатай байж болно.
- Хүлээлт (I/O загвар) нь хүлээлтийг загварчилдаг; CPU тооцоолол нь бодит арифметик үйлдэл хийдэг. Ажиллагчдын тоог нэмэхэд гүйцэтгэлийн хугацаа үргэлж ижил харьцаагаар багасахгүй.
- `shutdown()` нь хүлээж буй ажлуудыг цуцалж, ажиллаж буй урсгалуудад `interrupt()` илгээдэг. Тасалдлыг үл тоодог өөр төрлийн `Runnable` байвал шууд зогсохгүй байж болно.
