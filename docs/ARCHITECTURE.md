# Системийн зохиомж — №9 Урсгалын сан

```text
    Хэрэглэгчийн UI тохиргоо (ажиллагч, багтаамж, ажил, хугацаа)
                               |
              Сан үүсгэх / Ажил нэмэх / Зогсоох
                               |
                   ThreadPool үндсэн цөм
                  synchronized FIFO queue
                      wait/notifyAll
                   /         |         \
             Worker 1    Worker 2    Worker N
                   \        |        /
                    Runnable.run()
                           |
             Бодит төлөв ба үйл явдлын бүртгэл
                           |
            Өөрчлөгдөшгүй Snapshot / Listener
                           |
               SwingUtilities.invokeLater
                           |
         Ажиллагчдын карт / Хугацааны шугам
        Ажлын дараалал / Ажлын түүх / Event Log
```

## Яагаад ийм зохиомж сонгосон бэ?

- `ThreadPool.java` номын Java API-г хэрэгжүүлнэ: `ThreadPool()`, `ThreadPool(int)`, `add(Runnable)`, `shutdown()`.
- Queue-г нэг `lock` монитор хамгаална. `wait()` нь `while` давталтаар шалгагдах тул худал сэрэлт (spurious wakeup) болон shutdown-д зөв хариу өгнө.
- `Runnable.run()` ажиллагааг **lock-оос гадуур** хийснээр олон ажиллагч үнэхээр зэрэгцэн ажиллах боломжтой.
- `Event` нь `System.nanoTime()`-аар хэмжсэн өнгөрсөн хугацаанд суурилна; Java UI өөрөө хугацаа зохиодоггүй.
- ThreadPool snapshot нь хэрэглэгчийн UI-д immutable өгөгдөл болгон дамжина; Swing-ийн Event Dispatch Thread дээр л харагдац шинэчлэгдэнэ.
- `Completed` нь task-ийн төгсгөлийн төлөв, ажиллагчийн тухайн агшны event. Үүний дараа ажиллагч `Idle` болно.
- `shutdown()` нь Java номын хувилбарт нийцүүлж `interrupt()` ашиглана. Хүлээсэн task-уудыг цуцалж, гүйцэтгэж буй ажлыг таслахыг оролдоно.
- `Reset`-ийг туслах thread дээр хийдэг тул UI зогсохгүй. Хуучин урсгалууд эцэслэсний дараа шинэ pool үүсгэнэ.

**Багийн ажил:** 1-р гишүүн — үндсэн код/synchronization; 2-р гишүүн — UI/контрол; 3-р гишүүн — timeline, интеграц, тест/тайлан. Бүгд кодыг хамт шалгана.


## Хугацааны шугамын төгсгөлийн төлөв

Зогссон worker-ийг үргэлжилсэн улаан хугацааны интервал гэж тайлбарлахгүй. `STOPPED` event-ийн цэг хүртэл өмнөх `IDLE` эсвэл `RUNNING` интервалыг зурна. Дараа нь зөвхөн нарийн улаан босоо тэмдэг зурна. `COMPLETED` event-ийн агшинд цэнхэр босоо тэмдэг гарч, worker цаашид ажил хүлээвэл `IDLE` (саарал) болно. Pool бүрэн зогссон бол Timeline болон UI-д харуулах өнгөрсөн хугацааг сүүлийн `STOPPED` event-ээр царцаана.
